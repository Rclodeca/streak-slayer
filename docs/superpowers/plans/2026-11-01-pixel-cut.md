# Pixel-cut Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Ashen look with Pixel-cut for Moonlit: skill cards with a press-to-strike damage button, rank pips, struck = grey (option A), quest cards with a square checkbox, and pixel-cut corners, bevels and lips across the whole UI. Moonlit becomes the only theme.

**Architecture:** `themes/ashen.scss` evolves in place and keeps its family selector, which now matches Moonlit only (same specificity, so it still outranks scoped styles). New palette tokens go in `moonlit.scss`. Two new components hold their own look in scoped styles from tokens: `StrikeButton.vue` (the press button) and `RankPips.vue` (replaces `RankDiamonds.vue`). Every other screen is restyled from ashen.scss with shared mixins (`pixel-corners`, `bevel`, `lip-press`, `square-check`).

**Tech Stack:** Vue 3, Pinia, SCSS (Dart Sass), Vitest + @vue/test-utils (jsdom), playwright-cli skill for screenshots.

**Spec:** `docs/superpowers/specs/2026-11-01-pixel-cut-design.md`; visual source of truth `docs/mockups/pixel-done.html`, option **A (Grey)** (the `.lift.o-grey` column).

## Global Constraints

- Build directly on `main`, one commit per task. Do not push (pushing `main` deploys to GitHub Pages); the user pushes after review.
- Colours come from tokens in `moonlit.scss`, not literals in components. Every new token is added to `PALETTE_TOKENS` in `themes.spec.ts`.
- Stepped corners: 3px on cards and panels, 2px on buttons, checkboxes, the menu and add buttons, via `clip-path` polygons (the mock's `--px` / `--px2`). Bevels are 2px inset shadows. No rounded box corners. Round by nature stays round: quest difficulty pips, Overdrive charge dots, rings (ProgressSummary, level-up), the hero/boss platform ellipses, the death-screen embers.
- Tap targets ≥ 44px. Nothing important behind hover; hover effects only under `@media (hover: hover)`.
- No blur, no `filter` on rows, no new costly animation. Reduced motion: no landing flash.
- Icons only from `src/components/ui/statIcons.ts`.
- Order unchanged: healing, physical, magic, true; Resting folds under Daily; Resist is daily, weekly, resting; quests by soonest due.
- Player copy stays terse. New copy is fixed: hint text `Strike it.` (good habits) and `Tap it.` (bad habits).
- `clip-path` clips outlines and outer shadows: clipped focusable controls use an inset focus ring (`outline-offset: -3px`).
- Don't refactor the components' base (scoped) styles beyond removing markup that no longer exists.

## Review Focus

1. **Tapping a struck or resting card** (its button disabled) must open the skill popup, not swallow the tap. Disabled buttons get `pointer-events: none`. (Task 3 test.)
2. **Long names and wide numbers at 320px** ("Finish the quarterly tax return" with a sigil, damage "12.3K"): the name wraps, the button never shrinks (`flex: none`), no horizontal scroll. (Task 7 screenshot check.)
3. **Keyboard focus on clipped controls**: a Tab-focused strike button, add button, menu button and primary button show a visible inset ring. (Task 7 check.)
4. **A resting bad habit in Resist** is flat and unpressable like a resting skill; a struck one is grey like option A, not red. (Task 3 test + Task 7 screenshot.)
5. **An Overdrive skill after its last charge**: button grey, pressed, disabled; with charges left it stays grey and pressed but tappable, haloed, labelled "Overdrive {name}". (Task 3 test.)
